# Обобщённый формат хранения свойств

В движке используется обобщённый формат хранения данных в виде пар "ключ-значение".
Данный пары называются свойствами. Такой формат является простым и гибким.

## Описание формата

Ключом может быть строковое имя, состоящее из ASCII-символов. В рамках одного хранилища имя
должно быть уникальным.

Значение может принимать один из заранее определённых типов:

 * `uint64` - 64-битное беззнаковое целое число.
 * `uint32` - 32-битное беззнаковое целое число.
 * `uint16` - 16-битное беззнаковое целое число.
 * `uint8` - 8-битное беззнаковое целое число.
 * `int64` - 64-битное знаковое целое число.
 * `int32` - 32-битное знаковое целое число.
 * `int16` - 16-битное знаковое целое число.
 * `int8` - 8-битное знаковое целое число.
 * `bool` - булевый тип данных.
 * `float` - тип данных с плавающей запятой.
 * `double` - тип данных с плавающей запятой с двойной точностью.
 * `string` - строка из ASCII-символов.
 * `uint64_arr` - массив значений типа `uint64` произвольной длины.
 * `uint32_arr` - массив значений типа `uint32` произвольной длины.
 * `uint16_arr` - массив значений типа `uint16` произвольной длины.
 * `uint8_arr` - массив значений типа `uint8` произвольной длины.
 * `int64_arr` - массив значений типа `int64` произвольной длины.
 * `int32_arr` - массив значений типа `int32` произвольной длины.
 * `int16_arr` - массив значений типа `int16` произвольной длины.
 * `int8_arr` - массив значений типа `int8` произвольной длины.
 * `bool_arr` - массив значений типа `bool` произвольной длины.
 * `float_arr` - массив значений типа `float` произвольной длины.
 * `double_arr` - массив значений типа `double` произвольной длины.
 * `string_arr` - массив значений типа `string` произвольной длины.
 * `vec2f` - вектор длины 2 значений типа `float`.
 * `vec3f` - вектор длины 3 значений типа `float`.
 * `vec4f` - вектор длины 4 значений типа `float`.
 * `vec2i` - вектор длины 2 целочисленных знаковых значений, зависимых от платформы (тип `int` на платформе).
 * `vec3i` - вектор длины 3 целочисленных знаковых значений, зависимых от платформы (тип `int` на платформе).
 * `vec4i` - вектор длины 4 целочисленных знаковых значений, зависимых от платформы (тип `int` на платформе).
 * `float_rect` - прямоугольник, определённый двумя векторами `vec2f`, обозначающими левый верхний и правый нижний углы.
 * `int_rect` - прямоугольник, определённый двумя векторами `vec2i`, обозначающими левый верхний и правый нижний углы.
 * `resource_index` - идентификатор ресурса в пакете ресурсов, эквивалентен `uint16_arr` длины 2, где первое число -
номер пакета в текущем списке пакетов (зависит от контекста использования), а второе - номер ресурса внутри пакета.
Номер пакета 65535 зарезервирован и обозначает внутренний (или текущий) пакет.

В разных компонентах движка необходимо сохранять произвольные данные - тогда используется данный обобщённый формат.
В условных обозначениях может быть задано ограничение на длину массивов, обозначаемое в квадратных скобках. Например,
`uint16_arr[N]`, где `N` - длина массива. Данное обозначение является условным и никак не проверяется (в этом случае
пользователь сам в ответе за проверку длины массивов).

### Описание реализации на C++

Обобщённый формат хранения данных поддерживается в конкретных форматах хранения данных. Например, хранилище
пар "ключ-значение" реализовано в формате JSON или flatbuffers.

Существует абстрактный программный интерфейс, независимый от конкретного формата хранения данных, см.
`_16nar::tools::IPropsWriter` - для записи хранилища и `_16nar::tools::IPropsReader` - для чтения хранилища.
Для записи предусмотрены методы `set_<тип>`, а для чтения - методы `get_<тип>`. При этом, если происходит
попытка получения несуществующего свойства, будет возвращён пустой объект `std::optional`.

### Запрещённые операции

Поведение при сохранении более одного свойства с одинаковым именем является неопределённым, поэтому так
делать нельзя. Также не определено поведение при попытке чтения из хранилища, содержащего более одного
свойства с одинаковым именем.

Если какое-либо поле было сохранено с типом `A`, то чтение его как тип `B != A` является неопределённым
поведением.

## Схема данных

Для хранения метаинформации о свойствах используется схема данных. С её помощью можно получить необходимую
информацию для чтения и записи хранилища свойств. Схема данных содержит следующую информацию о свойствах
в хранилище: тип, имя, признак обязательности, значение по умолчанию. Схема данных не содержит самих свойств,
так что одна и та же схема может быть применена к нескольким хранилищам свойств.

Значения по умолчанию могут быть только у обязательных полей.

Значения по умолчанию, содержащиеся в схеме данных, тоже представляют собой хранилище свойств.

Схема данных является ресурсом и может храниться в пакете ресурсов.
