# Верхнеуровневая архитектура {#top_level_arch}

## Введение

Игровой движок Шеснарь - это фреймворк для построения приложений (видеоигр).

В общем случае, игра представляет собой приложение, построенное на фреймворке
движка и содержащее различные данные: текстуры, звуки, скрипты и др.

![Видеоигра](16nar_context.png)


## Уровни

Для разработки разных игр могут потребоваться разные возможности движка, в то время
как другие возможности будут не нужны. Движок Шеснарь построен таким образом, чтобы
пользователь не платил за то, что ему не нужно, и мог конфигурировать сборку движка
под себя таким образом, чтобы он содержал только нужный функционал.

Существуют различные парадигмы и стили разработки, которые нередко противоречат друг
другу. Разные стили подходят для разных игр. Например, для простых маленьких игр
достаточно примитивных возможностей движка, что позволит создать игру быстро, не
задумываясь о сложной архитектуре и разделении логики по подсистемам. А для более
масштабных проектов требуется задействовать более сложную функциональность движка:
ECS (Entity-Component-System), многопоточность, сложные скрипты и др.

**Профиль движка** - это набор настроек, определяющий стиль разработки игры на
движке. Движок определяет набор профилей, из которых можно выбрать один, с которым
движок будет собран. С точки зрения разработки, профиль определяет API фреймворка.

Шеснарь разделён на 3 уровня по гибкости настройки движка:

1. **[Platform](@ref arch_platform)** - точечно настраиваются отдельные функции во
время сборки, чаще всего, в зависимости от возможностей целевой платформы.
2. **[Core](@ref arch_core)** - настраиваются профили, определяемые во время сборки
движка.
3. **Plugin** - различная логика, реализованная под конкретный профиль, не требующая
пересборки движка для подключения.

![Уровни архитектуры движка](16nar_container.png)

Важно отметить, что эта архитектура не является слоистой архитектурой, а уровни не
являются слоями. В слоистой архитектуре слои выделяются по принципу разделения зон
ответственности и повышения абстракции. В архитектуре Шеснаря принцип разделения на
уровни принципиально другой - основанный на динамике конфигурации. При этом уровень
**Plugin** вполне может содержать, к примеру, реализацию низкоуровневых функций
отрисовки с помощью определённого графического API.


### Компоненты

Каждый уровень содержит логически обособленные компоненты, каждый из которых имеет
своё назначение.

![Компоненты движка](16nar_component.png)

#### Platform

Уровень **[Platform](@ref arch_platform)** содержит базовый функционал, необходимый
другим уровням. Как правило, это абстракция над системными функциями или фундаментальный
функционал, реализованный сторонними библиотеками.

Компоненты уровня **Platform**:

* **Math**- математические функции.
* **System** - абстракция над системными фугкциями: файловый ввод-вывод, загрузка
динамических библиотек и др.
* **Logger** - логирование.
* **Memory** - домены памяти и управление ими.
* **Execution** - (планируется) абстракция потоков и задач.


#### Core

Уровень **Core** содержит модули, конфигурируемые при сборке движка. При этом модули,
как правило, либо содержат базовую реализацию, либо вообще предоставляют только
интерфейс, который реализуется в модулях уровня **Plugin**. В отличие от уровня
**Platform**, который имеет общее назначение, уровень **Core** выстраивает определённый
профиль движка. Выбор пофиля осуществляется при сборке и не может меняться динамически.
Уровень **Core** предоставляет интерфейсы для использования и подключения плагинов
с модуля **Plugin**.

Компоненты уровня **Core**:

* **Assets** - чтение ассетов в разных форматах, без знания специфики.
* **Resources** - управление ресурсами с помощью хэндлов, чтение ассетов с ресурсами.
* **Config** - конфигурация статическая (из параметров сборки) и динамическая (из файла).
* **Actions** - назначение действий на события ввода от пользователя.
* **Loader** - загрузка плагинов и управление ими.
* **ECS** - реализация базового каркаса ECS, чтобы плагины могли подключать
свои компоненты и системы.


#### Plugin

Уровень **Plugin** содержит модули-плагины, которые можно подключать в зависимости
от конфигурации, не пересобирая движок. Каждый плагин работает с определённой
версией и профилем уровня **Core**.

Примеры плагинов (планируются):

* **VulkanRender** - отрисовка на Vulkan.
* **Physics** - физика.
* Пользовательские плагины.
